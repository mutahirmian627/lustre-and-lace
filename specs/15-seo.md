# SEO Specification

Per-page metadata for Product and Category pages (title/description/OG image/JSON-LD `Product` and `CollectionPage` structured data) is **already fully specified in `specs/06`** — not repeated here. This document covers everything site-wide that wasn't page-specific: root metadata defaults, sitemap, robots, sitewide structured data, and the Core Web Vitals discipline that underpins all of it.

## Root metadata defaults (`app/layout.tsx`)

- `title`: a template — `"%s | Lustre & Lace"` — so every page's specific title (set via each page's own `generateMetadata`) gets the brand suffix automatically, with a sitewide default (`"Lustre & Lace — Where Every Sparkle Tells Your Story"`) for any page that doesn't override it.
- `description`: a default sitewide description (brand + category summary — Wedding, Party, Everyday jewellery for women) for pages without a more specific one.
- Default Open Graph image: a single branded fallback image (logo/wordmark on the Cream background) used when a specific page (like a PDP with product photos) doesn't provide its own.
- `favicon` + `apple-touch-icon` + `theme-color` (set to the Rose Gold or Cream brand color, so mobile browser chrome tints on-brand).
- A placeholder `<meta name="google-site-verification" ...>` slot — **left empty until the real verification code is generated** once the site is live and added to Google Search Console; flagged so it isn't forgotten, not filled with a fake value now.

## Sitemap (`app/sitemap.ts`)

- **Static routes:** homepage, `/products`, `/search`, `/cart`, `/wishlist`, `/track-order`, about/contact/policy pages, login/register (generally low-priority for search but harmless to include).
- **Dynamic routes:** every active (`isActive = true`, `deletedAt IS NULL`) product's `/products/[slug]` and every active category's `/categories/[slug]` — generated by querying the database at build/request time, not hand-maintained.
- **Explicitly excluded:** everything under `(account)`, `(admin)`, and `/api` — these are private/protected areas with no business being indexed, and shouldn't appear in a sitemap even though `robots.ts` (below) already blocks crawling them — belt-and-suspenders.
- `lastModified` per entry uses each product/category's `updatedAt`, so search engines get accurate freshness signals instead of a blanket "now" timestamp.

## Robots (`app/robots.ts`)

- `Allow: /` for the general storefront.
- `Disallow: /account`, `/admin`, `/api`, `/checkout`, `/cart` — checkout and cart are user-specific/transient and have no SEO value; account/admin are private; API routes shouldn't be crawled.
- Sitemap reference pointing at `app/sitemap.ts`'s output.

## Sitewide structured data

- **`Organization`** JSON-LD on the homepage: brand name, logo, social links (Instagram), `sameAs` array — helps search engines associate the brand entity correctly (relevant for how the business shows up in knowledge-panel-style results).
- **`BreadcrumbList`** JSON-LD on every page that has a breadcrumb in its UI (category pages, PDPs — both already specified to have breadcrumbs in `specs/06`) — this is a straightforward structured-data mirror of UI that already exists, not new UI.
- **Not pursued for v1:** `LocalBusiness` structured data (would imply a physical storefront location, which doesn't apply to an online-only jewellery boutico at this stage) — skip unless a physical location is added later.

## Core Web Vitals — a checklist, not new decisions

Everything here was already decided elsewhere in the spec set; this section exists purely so it's visible as a single checklist rather than scattered:
- Server Components by default, Suspense boundaries around slower sections (homepage product rows per `specs/05`, PDP reviews/related products per `specs/06`) — already specified.
- `next/image` everywhere, with explicit `width`/`height` (or `fill` + sized container) to avoid layout shift, and meaningful `alt` text on every product image (not just the product name repeated — ideally including plating/variant context where relevant, e.g. "Rose Gold Plated Necklace, close-up") for both accessibility and image-search SEO.
- Skeletons sized to match their real content (already specified per-milestone) to avoid cumulative layout shift between skeleton and loaded state.
- Cloudinary handles image optimization/format negotiation (already in the stack) — no separate image-optimization decision needed here.

## What's intentionally out of scope for v1
- A dedicated blog/content-marketing section (would help SEO long-term via fresh content, but wasn't part of the original scope — flagged as a plausible future addition, not built now).
- Multi-language/hreflang setup — the site is single-language (English) for launch.
